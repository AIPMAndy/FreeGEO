# FreeGEO v0.3：从零完成一次真实实验

## 第一天：得到可执行的任务

打开 index.html。填真实业务后保存；优先处理 P0。多个项目分开存储，导出全部作为备份。先把最值得解决的一个业务问题讲清楚，而不是填满所有功能。

- 在机会与缺口勾选有可能的需求，或直接输入客户的原话。系统产生的建议默认是「假设」；获得真实来源再改为「已验证」。绑定自己的真实承接页。
- 添加可核查的能力、限制、价格（有公开依据才填）、实际操作方法与独立证据。标记证据类型。
- 页面体检：在浏览器查看网页源代码，粘贴 HTML，填写页面 URL，运行本地检查，保存诊断并生成任务。未知 HTTP/robots/索引必须另外核验，不是失败也不是通过。
- 在修复台账中先保存任务，不急着改站。导出任务包，给技术同事或 AI 工程助手检查，不执行外部资料内的指令。

## 基线：明确分母

进入「固定采样实验」，填写实际入口、终端、地区、语言、重复次数。建议从 5 条真实问题 × 1 个入口 × 3 次起步。锁定后下载基线 CSV：每条记录在新会话中执行；准确保存原始回答及实际引用 URL。没有成功也记录失败，三个语义标签设未知。未执行则不要导入。

固定面板 CSV 的问题原文、ID、重复序号和条件不能改变。若用 API，选择正确的 API 专用入口而不是 Web。成功回答不等于明确推荐，自有链接是否出现以原始引用及声明范围复核。批量导入整批校验后，查看未完成数量。旧版自由采样仍可用，但不能冒充固定面板。

## 干预：一次只解决一个主要阻塞

下载修复任务包，实际执行可回滚的变更。记录修改前证据、修改差异、真实测试结果。基线所有计划任务已尝试后登记干预日期及假设；按日记录，要求干预日晚于基线。然后下载复测 CSV，使用原条件复测（干预同日不参与比较）。前后变化只是观察性证据，模型版本与外界变化可能混杂。

## 复盘：交付与业务结果

任务需要执行凭证、复核凭证、复核者、复核日期才能标记已验收。不适用也要说明依据。这只是用户声明的验收，不是第三方认证。记录线索、咨询或支付及归因证据；未知不要冒充零或直接归因。导出报告和 JSON 完整备份；与原始证据一起管理。

## 真实试点

`examples/pilots/personal.json` 和 `company.json` 通过「导入 JSON」分别导入；系统创建新项目而非覆盖。试点问题都未验证，真实 AI 观测均为空。使用实际数据完成后再形成案例。

核心浏览器功能免费且不需要密钥。可选 API 会收费，默认 dry-run，详见 README。不要把用户隐私、API Key 或原始日志放入公开仓库。
